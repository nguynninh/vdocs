# ITR — API Reference Documentation

## Introduction

**ITR** (Integration & Reference — Integration and API Reference Documentation) is a complete reference for all the APIs that `vdocs-server` provides. This documentation is for developers who want to:

- Integrate VDocs into their own system, website, or application.
- Build a client/bot/automated service that interacts with VDocs.
- Understand the request/response structure, authentication mechanism, and possible error codes.

## Audience

This documentation is a good fit for:

- Backend/frontend developers who need to call the VDocs API.
- DevOps teams integrating VDocs into internal pipelines.
- Third-party partners integrating through the public API.

## Architecture overview

```
Client / Your application
        │
        │  HTTPS + Bearer Token
        ▼
   vdocs-server (ITR API)
        │
        ▼
   VDocs database
```

`vdocs-server` acts as the central API and socket server, handling authentication, storage, and real-time document synchronization (using Yjs).

## Base URL

| Environment | URL |
| --- | --- |
| Production | `https://api.vdocs.example.com` |
| Staging | `https://api.staging.vdocs.example.com` |

All endpoints in this documentation are relative to the Base URL — for example, `/itr/documents` corresponds to `https://api.vdocs.example.com/itr/documents`.

## Quick start

1. Register an account / get credentials from a VDocs administrator.
2. Call the [Authentication](/itr/authentication) API to get an access token.
3. Use the token to call the [Documents](/itr/documents) API or other API groups.
4. Handle errors using the [Error Codes](/itr/errors) table if a request fails.

### Quick cURL example

```bash
# 1. Log in to get a token
curl -X POST https://api.vdocs.example.com/itr/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"your-password"}'

# 2. Use the token to list documents
curl https://api.vdocs.example.com/itr/documents \
  -H "Authorization: Bearer <token>"
```

## Request format

- All request/response bodies use `Content-Type: application/json`.
- Dates and times follow ISO 8601, e.g. `2026-08-12T10:30:00Z`.
- Resource IDs are UUID strings.

## Response format

All API responses return JSON with a consistent structure:

```json
{
  "success": true,
  "data": {},
  "error": null
}
```

On error:

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request data"
  }
}
```

## Rate limiting

| Account type | Limit |
| --- | --- |
| Free | 60 requests/minute |
| Paid | 600 requests/minute |

When the limit is exceeded, the API returns HTTP `429 Too Many Requests`.
