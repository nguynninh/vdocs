## Configuration process

1. Configure on the Hub

    After configuring on the hub successfully and verifying by copying this data into the SDK to check whether the fields are correct, configure it on Firebase Remote Config the same way as other games.

![image.png](/images/sdkgame/dev_config/image-8.png)

    1. Global

        Applies to all apps, created automatically, no need to edit unless there's an error — report it to BE to fix. Default value is 0

    2. App

        Applies to all packages including iOS, the parameter is taken from appId

![image.png](/images/sdkgame/dev_config/image-6.png)

    1. Package

        Applies to a single package, taken from packageId

![image.png](/images/sdkgame/dev_config/image-10.png)

2. Configure on Firebase

    1. Configure the app

        Go to: Setting -> General -> Add app -> Enter the package Id

        After creating the app, **ask the team lead** to update the configuration on Google Cloud to fill in the info for google-service.json

        Check the json at: https://dandar3.github.io/android/google-services-json-to-xml.html

        It must be complete as shown

![image.png](/images/sdkgame/dev_config/image.png)

    2. Configure server notifications

        After configuring google-server.json correctly in the sample app, you should reliably receive notifications; you can test first using Firebase's message tool

        Project Setting -> Services account

        Make sure to create this only once and keep the file.

        When configuring for both Android and iOS on the Hub, retest notifications from the package's configuration on the hub

![image.png](/images/sdkgame/dev_config/image-7.png)

5. Sample test flow

    1. Regular login

        Failure -> Recheck the hub configuration and the sample project for the correct package and provided info -> if correct, ask BE whether login has been configured

    2. Registration and Forgot Password

        Failure -> Open the log and see the package name doesn't exist in recaptcha -> **ask the team lead** to configure it

        Failure -> A dialog shows a BE error -> the device and network are being flagged as spam by recaptcha, use a different device and 3G network

    3. Google login

        Info verification fails.

        Cause:

        -> The build isn't signed, or the signature on Google Cloud is wrong. Check that the APK, Google Cloud, and store all share the same SHA1 signature

        ! The GG login client ID on the hub may be set incorrectly

    4. Facebook login

        Reports unable to log in.

        In develop mode:

        Recheck Facebook's info in the app

        Make sure you're using the correct test account to log in

        In public mode:

        Check whether Facebook has granted the profile permission -> if not, **ask the team lead** to request the permission from Facebook for the project

    5. Check events on Appsflyer

        Open the log with the appsflyer tag; if it fires an error that the package name doesn't exist, **ask the team lead**

    6. Check payment

        To enable payment, push a build to internal testing, then configure the top-up package on the store and the hub

        If payment fails with an unknown error

        Check whether the APK is sending the correct top-up package name.

        If the game is sending the correct top-up package name but the BE API still returns an unknown error

        **Ask the team lead** to have the team lead notify the Payment team to enable it on production and configure the service on Google Cloud.

        Enabling this configuration can take up to 1 day before payment works

## Store configuration

1. App registration

    Registration must be done right away since it takes up to 48h to review the package name registration.

    After completing the sample project, create a file at the path

![store-register.png](/images/sdkgame/dev_config/store-register.png)

    The code is taken from the store when registering the package name

    Use the correct keystore, build the APK, and upload it to the store to register the package name

    Only after registering the package name can the app be created on the store
