## 1. 环境要求

| 项目 | 值 |
|---|---|
| `minSdk` | **21** |
| SDK 的 `compileSdk` / `targetSdk` | 35 |
| Java / Kotlin JVM 目标版本 | **1.8** |
| Kotlin 插件 | 1.7.10（依据示例仓库） |
| AGP | 8.6.1（`app` 示例模块使用 `com.android.application` 8.6.1） |
| NDK | **28.1.13356709**（仅在*构建* SDK 时需要，因为含有 native 库） |
| CMake | 3.22.1（构建 SDK 时） |
| Activity 类型 | **`FragmentActivity`**（通常是 `AppCompatActivity`） |

> SDK 中包含 native 库 `liboverlay.so`（隐藏了环境 URL）。以 `.aar` 文件方式集成时，
> `.so` 已内置于 AAR 中 —— 应用**无需**依赖 NDK/CMake。

## 2. 构建 AAR 文件

```bash
./gradlew :interactive:assembleRelease
```

产物位于 `interactive/build/outputs/aar/`，文件名遵循
[interactive/build.gradle](../interactive/build.gradle) 中的规则：

```
Interactive_<DEVICE_TYPE>_<buildType>_<构建日期>.aar
例如：Interactive_androidmobile_release_2026-07-30.aar
```

**为 Android TV 构建**：修改 `interactive/build.gradle` 中的
`buildConfigField("String", "DEVICE_TYPE", "\"androidtv\"")` 后重新构建。该值会影响：

- socket 请求头 `os`，
- 附加到 URL 模板的查询参数 `os=`，
- overlay 的 `targets` 过滤条件（`Utils.isValidTargets`），
- tracking 中的 `platform` / `deviceClass` 字段。

## 3. 声明依赖

### 方式 A —— 使用源码模块（如示例仓库）

`settings.gradle`：

```gradle
include ':interactive'
```

`app/build.gradle`：

```gradle
dependencies {
    implementation project(":interactive")
}
```

### 方式 B —— 使用 `.aar` 文件

将 AAR 复制到 `app/libs/`，然后：

```gradle
dependencies {
    implementation fileTree(include: ['*.jar', '*.aar'], dir: 'libs')
}
```

## 4. `AndroidManifest.xml` 中的权限与配置

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

<application
    android:usesCleartextTraffic="true">   <!-- 仅在 DEV 环境使用 http 时需要 -->
    <activity
        android:name=".MainActivity"
        android:configChanges="orientation|screenSize" />  <!-- 避免旋转时重建 Activity -->
```

SDK 会读取 `Settings.Secure.ANDROID_ID` 作为 `deviceId` —— 为此**无需额外声明权限**。

## 5. 在布局中添加 `OverlayView`

`OverlayView` 必须**精确覆盖视频显示区域**（通常为 16:9 画面），并在绘制顺序上
**位于**播放器**之上**（在同一个 `ConstraintLayout` 中声明于播放器之后，或使用 `elevation`）。

```xml
<androidx.constraintlayout.widget.ConstraintLayout
    android:layout_width="match_parent"
    android:layout_height="match_parent">

    <!-- 您的播放器 -->
    <FrameLayout
        android:id="@+id/player_container"
        android:layout_width="0dp"
        android:layout_height="0dp"
        app:layout_constraintDimensionRatio="H,16:9"
        app:layout_constraintTop_toTopOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent" />

    <!-- Overlay 覆盖在播放器之上，尺寸相同 -->
    <vn.interactive.widgets.OverlayView
        android:id="@+id/overlay_view"
        android:layout_width="0dp"
        android:layout_height="0dp"
        app:layout_constraintTop_toTopOf="@id/player_container"
        app:layout_constraintBottom_toBottomOf="@id/player_container"
        app:layout_constraintStart_toStartOf="@id/player_container"
        app:layout_constraintEnd_toEndOf="@id/player_container" />

</androidx.constraintlayout.widget.ConstraintLayout>
```

**为什么 `OverlayView` 的尺寸很重要？** Overlay 是按照 `OverlayView` 自身的
*百分比比例*进行定位的（`metadata.size.w/h` 取值范围为 `0..1`，以及
`metadata.pos.x/y`）。如果 `OverlayView` 比视频画面更大，overlay 就会偏离画面区域。

示例仓库在 `onResume` / `onConfigurationChanged` 中按 16:9 比例重新计算尺寸
（参见 [MainActivity.kt:151](../app/src/main/java/com/vtvlive/example/MainActivity.kt:151)）：

```kotlin
private fun resizeContentView() {
    contentView.viewTreeObserver.addOnPreDrawListener(object : ViewTreeObserver.OnPreDrawListener {
        override fun onPreDraw(): Boolean {
            contentView.viewTreeObserver.removeOnPreDrawListener(this)
            val screenWidth = contentView.width
            val calculatedHeight = (screenWidth * 9) / 16
            updateOverlayViewLayoutParams(screenWidth, contentView.height, calculatedHeight)
            return true
        }
    })
}
```

## 6. 初始化 SDK

```kotlin
class MainActivity : AppCompatActivity(), DefaultOverlayEventListener {

    private lateinit var overlayManager: OverlayManager

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        initInteractive()
    }

    private fun initInteractive() {
        val overlayData = OverlayData.Builder()
            .setEnvironment(EnvInteractive.PROD)   // DEV | STG | PROD，默认 PROD
            .setTenantId("vtvlive")                // 必填，由 Interactive 团队分配
            .setDebug(false)                       // 可选
            .build()

        overlayManager = OverlayManager(
            /* activity  */ this,
            /* overlayView */ findViewById(R.id.overlay_view),
            /* overlayData */ overlayData,
            /* listener */ this
        )
    }
}
```

构造函数**不会打开网络连接** —— 只加载配置。连接从 `joinRoom()` 开始。

## 7. 声明登录会话

```kotlin
// 登录成功时
overlayManager.initToken(
    token = accessToken,   // JWT（以 "ey" 开头）或 cookie 字符串
    userId = userId,       // 用户标识 id
    bjName = ""            // 可选：BJ/频道名称，显示在 fanclub 对话框中
)

// 登出时
overlayManager.initToken("", "")
```

机制说明：

- 以 `"ey"` 开头的 token → SDK 会自动为 socket 请求头和 REST 添加 `Bearer ` 前缀。
- 其他类型的 token（cookie）→ 原样发送。
- 若正在观看 **Live** 时调用 `initToken`，SDK 会**自动重新加入房间**，使 socket 携带新的 token。
- 首次进入时，需**先**调用 `initToken`，**再**调用 `joinRoom`。

## 8. 进入 / 离开内容

```kotlin
// LIVE
overlayManager.joinRoom(mediaId = "003c04ba-8f7d-4663-bef0-c7a971c059b6", type = 1)

// VOD
overlayManager.joinRoom(mediaId = "4357747e-004c-4190-a3f3-4a33840a3c09", type = 2)

// 退出内容 / 销毁画面
overlayManager.releaseAll()
```

- `type = 1` → LIVE（`Const.VIDEO_LIVE`），`type = 2` → VOD（`Const.VIDEO_VOD`）。
- `joinRoom` 会自动清理上一个会话，因此切换频道只需再次调用即可。
- `releaseAll()` 会关闭 socket（如果是 Live）、销毁全部 WebView、对话框、浮动按钮以及挂起的 tracking。

**进入房间前检查内容是否具有互动性**（可选）：

```kotlin
overlayManager.fetchInteractiveStatus(mediaId) { isInteractive ->
    if (isInteractive) overlayManager.joinRoom(mediaId, type = 1)
}
```

## 9. VOD 集成 —— 注入播放时间

对于 VOD，SDK **无法自行获知**播放器当前处于第几秒。应用必须每秒注入一次：

```kotlin
private val handler = Handler(Looper.getMainLooper())
private var seconds = 0

private val tick = object : Runnable {
    override fun run() {
        seconds = (player.currentPosition / 1000).toInt()   // 播放器当前的秒数
        overlayManager.receiveTrackingTime(seconds)         // 注入到 SDK
        handler.postDelayed(this, 1000L)
    }
}

// 在 joinRoom(type = 2) 之后开始
handler.post(tick)

// 离开内容时停止
handler.removeCallbacks(tick)
```

- 单位：**秒**（与 `Timeline.time` 的 `"mm:ss"` 格式对应）。
- SDK 会**精确按秒**匹配 overlay 的时间点（`startTimeShowOverlay == time`），因此**不能
  漏跳**：如果 tick 间隔超过 1 秒，或用户跳过了某个时间点，该时间点的 overlay 将不会显示。
- `receiveTrackingTime` 是一个类型为 `(Int) -> Unit` 的属性，像普通函数一样调用即可。

## 10. 向 SDK 提供播放器状态（可选，仅 Live）

服务器可能会发送 `ckst` 事件来询问客户端当前是在播放还是暂停。若要准确响应，请注册：

```kotlin
overlayManager.addPlayerListener(object : PlayerChangeListener {
    override suspend fun currentPosition(): Long = player.currentPosition

    // first = isPlaying，second = state（1 = IDLE，2 = BUFFERING，3 = READY，4 = ENDED）
    override fun onPlayerStateChanged(): Pair<Boolean, Int> =
        Pair(player.isPlaying, player.playbackState)
})
```

SDK 的映射规则：`1 → "idle"`，`3 → 根据 isPlaying 取 "playing"/"paused"`，其余情况 → 空字符串。

> 若希望监听器也被绑定到 `SocketIOManagement`（该对象仅在进入 Live 房间后才存在），
> 请在 `joinRoom` **之后**再调用 `addPlayerListener`。

## 11. 接收 SDK 事件

```kotlin
class MainActivity : AppCompatActivity(), DefaultOverlayEventListener {

    /** Overlay 请求应用需要处理的动作 */
    override fun onHandleMessage(msg: EventOverlay) {
        when (msg) {
            EventOverlay.NEED_LOGIN   -> showLoginScreen()   // 用户在未登录状态下点击回答
            EventOverlay.NEED_PAY_ONG -> showTopUpScreen()   // 服务器返回 PM402 错误码（OnG 不足）
            else -> Unit
        }
    }

    /** 频道的实时观看人数（仅 Live 才有） */
    override fun onHandleLiveViews(liveViews: Int) {
        tvViewers.text = liveViews.toString()
    }

    /** Overlay 打开/关闭统计部分 —— 如需可用于隐藏/显示应用的 UI */
    override fun onShowITR(show: Boolean) { }

    /**
     * Overlay 已加载完成（takeControl = true）或加载出错（webViewError = true）。
     * overlayConfig 指明这是弹窗还是内嵌形式、对齐方式（上/下）以及高度比例。
     */
    override fun onFocusOverlay(
        takeControl: Boolean,
        webViewError: Boolean,
        overlayConfig: OverlayConfig?
    ) {
        if (overlayConfig?.popupOverlay == true) {
            // 例如：将播放器控制条上移，避免被 overlay 遮挡
        }
    }
}
```

`DefaultOverlayEventListener` 只是 `OverlayEventListener` 的别名 —— 实现哪一个都可以，
但**4 个函数都必须实现**。

## 13. 处理屏幕旋转

声明 `android:configChanges="orientation|screenSize"`，使 Activity **不会被重建** ——
这样 overlay/socket 就不会丢失。SDK 的各个对话框会自行处理各自的 `onConfigurationChanged`。

> 注意：`OverlayManager.onConfigurationChanged` 目前是 **private** 的，应用无法直接调用。
> 如果 Activity 在旋转时被重建，请重新构建 `OverlayManager` 并重新调用 `joinRoom`。

## 14. ProGuard / R8

`:interactive` 模块已附带 `consumer-rules.pro`（使用 AAR 时会自动应用到应用中），保留了：

- Retrofit 接口 `OverlayService`、`InteractiveStatusService`，
- 全部 `vn.interactive.model.**`、`retrofit2.**`、`okhttp3.**`、`okio.**`、Gson 以及相关 annotation。

如果应用启用了 `minifyEnabled true` 并遇到 JS bridge 未被调用的错误，请补充：

```proguard
# 保留 JS interface（WebView 通过反射调用）
-keepclassmembers class vn.interactive.callbacks.OverlayWebViewCallBack {
    @android.webkit.JavascriptInterface <methods>;
}
-keepclassmembers class vn.interactive.callbacks.PostMessageListener {
    @android.webkit.JavascriptInterface <methods>;
}

# 保留获取环境 URL 的 native 函数
-keepclasseswithmembernames class vn.interactive.utils.Utils {
    native <methods>;
}
```

## 15. 集成检查清单

- [ ] Activity 继承自 `AppCompatActivity` / `FragmentActivity`。
- [ ] `OverlayView` 位于布局中，精确覆盖视频画面，绘制在播放器**之上**。
- [ ] 已声明 `INTERNET` + `ACCESS_NETWORK_STATE`。
- [ ] 已声明齐全的依赖（若使用 AAR 集成）。
- [ ] `setTenantId(...)` 的值正确，由 Interactive 团队分配。
- [ ] 登录**及**登出时都调用了 `initToken()`。
- [ ] 每次开始观看新内容时都调用了 `joinRoom()`。
- [ ] VOD：已有每秒调用一次 `receiveTrackingTime()` 的循环。
- [ ] 离开内容 / `onDestroy()` 时调用了 `releaseAll()`。
- [ ] 已处理 `EventOverlay.NEED_LOGIN` 和 `NEED_PAY_ONG`。
