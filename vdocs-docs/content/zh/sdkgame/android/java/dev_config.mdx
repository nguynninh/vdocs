## 配置流程

1. 在 Hub 上配置

    在 hub 上配置成功后，通过将该数据复制到 sdk 中检查各字段是否正确，然后像其他游戏一样将其配置到 firebase remote config 上。

        适用于所有自动创建的应用，无需修改，除非出现错误需通知 BE 修改。默认值为 0

    2. App

5. 示例测试流程

    1. 普通登录

        失败 -> 重新检查 hub 配置及示例项目的 package 和所提供信息是否正确 -> 正确则询问 BE 是否已配置登录

    2. 注册与忘记密码

        失败 -> 打开日志发现 recaptcha 中 package name 不存在 -> **请主管**配置

        失败 -> 显示 BE 返回的错误弹窗 -> 设备和网络被 recaptcha 判定为垃圾请求，请更换设备及使用其他 3G 网络

    3. Google 登录

        信息验证失败。

        原因：

        -> 构建未签名，或 google cloud 上的签名错误。需检查 Apk、google cloud、store 三处的 sha1 签名是否一致

        ! 也可能是 hub 上设置的 GG login client ID 错误

    4. Facebook 登录

        报告无法登录。

        在 develop 模式下：

        重新检查应用中 facebook 的信息

        确认是否使用了正确的测试账号登录

        在 public 模式下：

        检查 facebook 是否已授予 profile 权限 -> 若未授予，**请主管**向 facebook 为该项目申请权限

    5. 检查 appsflyer 事件

        打开带 appsflyer 标签的日志，若上报错误显示 package name 不存在，**请主管**处理

    6. 检查支付

        要实现支付，需先推送一个版本到内部测试，然后在 store 和 hub 上配置充值套餐

        若支付失败并返回未知错误

        检查 apk 是否已正确传递充值套餐名称。

        若游戏方已正确传递充值套餐名称，但 BE api 仍返回未知错误

        **请主管**通知支付团队在生产环境开启支付，并在 google cloud 上配置开启相应服务。

        开启此配置最长需要 1 天才能完成支付

## Store 配置

1. 应用注册

    注册需立即进行，因为审核 package name 注册最长需要 48 小时。

    完成示例项目后，按以下路径创建文件

![store-register.png](/images/sdkgame/dev_config/store-register.png)

    该代码是在 store 上注册 package name 时获取的

    使用正确的 keystore 构建 apk，并上传到 store 以注册 package name

    只有注册了 package name 后，才能在 store 上创建该应用
